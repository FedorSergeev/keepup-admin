## Why

0.5.0 — релиз, в котором возможности окончательно уехали в отдельные
дистрибутивы, и `pip install keepup-admin` перестал ставить панель: база — это
конструктор, без `keepup-http`, без входа и без базы данных. Страница пакета
говорила только «pip install keepup-admin» и не называла ни экстров, ни сборки,
ни того, что перед прогоном набора пакет надо поставить: в клоне каталог
называется `keepup-admin`, поэтому `import keepup` не резолвится и pytest
падает на сборе. Обе ошибки тихие — страница выглядит правильно, а команда не
работает.

## What Changes

- `INSTALL.md` — длинная форма: требования, база и экстры (что каждая
  возможность отдаёт и какие библиотеки приносит), установка из репозитория,
  сборка всех дистрибутивов и `twine check`, релиз по тегу
  (`release_versions.py`, Trusted Publishing), прогон набора с покрытием,
  тяжёлые проверки (`KEEPUP_PACKAGING_TESTS=1`, security audit) и разбор
  частых ошибок.
- `README.md` — короткая форма: разделы Install, Build и Tests с теми же
  командами и ссылкой на `INSTALL.md`; дублирующий «Requirements» влит в
  Install, а пример на первой странице говорит, что шелл и секции едут с
  возможностями. Со страницы убрано рассуждение о бейджах — почему их четыре,
  а не шесть и что бейдж ничего не запрещает: это решение репозитория, и его
  место там, где оно проверяется, а не на витрине пакета; заодно ушла ссылка на
  `doc/keepup.md`, которого в этом репозитории нет.
- `tests/install_guide_tests.py` — страницы держатся за метаданные: имя
  дистрибутива, список экстров, все четырнадцать `packages/*`, версия Python из
  `requires-python`; команды установки и теста сверяются с `tests.yml`, сборка —
  с `build.yml`; отдельная проверка требует, чтобы было сказано «Install
  first».
- `tests/badges_tests.py` — проверка «бейдж не запрещает merge» уходит вместе с
  абзацем, который её держал; адреса и порядок бейджей проверяются как прежде.
- CHANGELOG 0.5.0 — пункт о задаче.
