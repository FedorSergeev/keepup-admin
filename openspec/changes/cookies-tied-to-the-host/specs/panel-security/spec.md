## ADDED Requirements

### Requirement: Cookie панели привязаны к хосту по HTTPS

Ответ, ставящий cookie сессии и метки CSRF, SHALL по HTTPS использовать имена
`__Host-ss_session` и `__Host-ss_csrf` с атрибутами `Secure`, `Path=/` и без
`Domain`; по HTTP имена SHALL оставаться `ss_session` и `ss_csrf`, потому что
cookie с префиксом `__Host-` без `Secure` браузер не сохраняет. Сервер SHALL
читать сессию из обоих имён ещё один выпуск, отдавая предпочтение префиксному,
и SHALL гасить простые имена, когда ставит префиксные. Имена SHALL быть
опубликованы каркасом (`cookie_names`, `session_token_in`), а не строкой в
приложении. Выход SHALL гасить cookie обоих имён.

#### Scenario: Панель по HTTPS

- **WHEN** пользователь входит в панель по HTTPS
- **THEN** ответ ставит `__Host-ss_session` и `__Host-ss_csrf` с `Secure`, `Path=/` и без `Domain`, а простые имена гасит

#### Scenario: Стенд без TLS

- **WHEN** панель открыта по HTTP
- **THEN** имена прежние — `ss_session` и `ss_csrf` — и cookie не несёт `Secure`

#### Scenario: Сессия, открытая до обновления

- **WHEN** запрос несёт только простое имя сессии, поставленное прошлым выпуском
- **THEN** запрос принят, а на следующем чтении метка CSRF приходит под префиксным именем

#### Scenario: Подложенная cookie

- **WHEN** запрос несёт и префиксное имя сессии, и простое, поставленное соседним поддоменом
- **THEN** сервер берёт префиксное; простое, названное без префиксного, доступа не даёт

#### Scenario: Выход

- **WHEN** пользователь выходит из панели
- **THEN** ответ гасит и префиксные, и простые имена сессии и метки
