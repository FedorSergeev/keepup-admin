## Why

Cookie панели — `ss_session` (HttpOnly) и `ss_csrf` — ставятся без префикса,
и это остаток находки 13 аудита безопасности после 0.2 (keepup-52). Cookie без
префикса может выставить любой поддомен хоста: браузер отправит её на панель
вместе с настоящей, а сервер читал имя и брал то, что нашёл. Тем же способом
cookie подкладывается через переход по HTTP. Префикс `__Host-` закрывает это
на стороне браузера: такую cookie принимают только от того самого хоста,
только с `Secure`, только с `Path=/` и никогда с `Domain`.

В keepup-72 префикс отложили, потому что имена читают приложения — в ServerShare
это доступ к мониторингу, — и потому что имена каркас не публиковал: строку
`ss_session` приложение знало само. Обе причины сняты: имена публикуются, а
старые читаются ещё один выпуск, чтобы открытые сессии не оборвались.

## What Changes

- `keepup.auth.panel_session` публикует имена: `HOST_PREFIX`, `cookie_names
  (secure)` и `session_token_in(cookies)`; приложение читает имя оттуда, а не
  строкой.
- По HTTPS каркас ставит `__Host-ss_session` и `__Host-ss_csrf` (Secure,
  Path=/, без Domain) и гасит старые имена; по HTTP имена прежние, потому что
  `__Host-` без `Secure` браузер не сохранит.
- Чтение принимает оба имени один выпуск; при наличии обоих побеждает
  префиксное — именно его не может выставить соседний поддомен.
- `CsrfCookieRefresh` кладёт значение метки под имя своей схемы и на HTTPS
  убирает старое; выход гасит cookie обеих схем и обоих выпусков.
- Панельный скрипт читает метку из обоих имён, префиксное первым.
