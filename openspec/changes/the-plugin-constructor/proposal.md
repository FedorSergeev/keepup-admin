## Why

0.3.0 не умеет собираться из частей: `create_app()` — линейный сценарий из
одиннадцати `register_*`, шести посредников, двух монтирований и lifespan из
десяти задач, а перечень возможностей негде объявить — каталог собирается из
одного файла приложения без встроенных умолчаний каркаса. Плагин может
добавить маршрут поверх готового набора, но не может ни принести возможность,
ни заменить её, ни отсутствовать так, чтобы ядро это вынесло.

Отсюда три следствия, ради которых заводится ядро: развёртывание не может быть
меньше каркаса, не может быть не-HTTP, и исправление в одной возможности
выходит выпуском всех.

## What Changes

- Новый пакет `keepup/kernel/`: дескриптор плагина, каталог (встроенный файл
  каркаса, файл приложения, профиль, окружение), загрузчик (точка входа
  `keepup.plugins` и каталог плагинов приложения), реестр служб и жизненный
  цикл с отдельной фазой регистрации служб до `initialize()`.
- `PluginDescriptor` — классовый атрибут: `id`, `name`, `version`,
  `distribution`, `priority`, `requires`, `wants`, `provides`,
  `contributions`, `kind`, `default_enabled`, `config_schema`. Плагин без
  дескриптора — плагин 0.3.0: идентификатор выводится из имени файла, требования
  пусты.
- `keepup/plugins/builtin.json` — встроенный каталог: каркас объявляет свои
  плагины, не импортируя их.
- Двухфазное разрешение: сперва обязательный набор из встроенного каталога,
  файла приложения и окружения; решение администратора читается позже, после
  того как поднялся источник данных.
- Виды плагинов: `required` (не выключается ни панелью, ни переменной
  окружения, объявляет `check()`), `optional`, `transport`. Две службы одного
  обязательного имени — отказ старта с именами обоих.
- `wants` — необязательное требование: плагин запускается, отчёт помечает его
  `degraded` и называет недостающую службу.
- Состояние переезжает из модульных глобальных переменных в состояние
  экземпляра ядра: два приложения в одном процессе больше не делят значения
  второго.
- `KeepupSettings.plugins_dir` перестаёт быть мёртвым полем: менеджер строит
  ядро, а не приложение.

## Capabilities

### New Capabilities

- `plugin-constructor`: ядро знает о возможностях только имена служб и точек
  вклада; состав развёртывания задаётся каталогом, профилем и окружением, а
  порядок запуска двухфазный.
